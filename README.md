# 앵커 이벤트 매퍼

카카오페이증권의 초보 투자자와 주니어 리서처가 뉴스·공시·정책·루머성 문장을 바로 매수·매도 판단으로 연결하지 않고, 어떤 산업과 기업으로 어떤 경로를 통해 번질 수 있는지 구조화해 보는 상황 해석·리서치 학습 도구입니다.

## 현재 제품 방향

이 프로젝트는 주가 예측기나 매수·매도 추천기가 아닙니다.

핵심 가치는 `이 뉴스가 왜 이 종목과 연결되는지`를 보여주는 것입니다.

예를 들어 `엔비디아 HBM 수요 확대`라는 상황이 들어오면, 단순히 “SK하이닉스 호재”라고 끝내지 않고 다음을 분리합니다.

- 0차 상황: 엔비디아 HBM 수요 확대
- 1차 영향: HBM 공급사 수요 증가 가능성
- 2차 영향: SK하이닉스 직접 수혜 가능성
- 3차 영향: 삼성전자 HBM/파운드리 경쟁구도 변화
- 4차 영향: 장비·소재·부품주로의 간접 파급 가능성

각 연결고리에는 방향성, 직접성, 확신도, 선반영 가능성, 확인해야 할 데이터를 붙입니다.

주요 타겟:

- 일반 투자자: 뉴스와 종목의 연결고리를 이해하고 과신을 줄이는 용도
- 주니어 애널리스트/리서치 입문자: 리서치 초안과 확인 체크리스트를 빠르게 만드는 용도
- 시니어 애널리스트: 콘텐츠 소비자보다는 검토·교육·워크플로우 자동화 관점의 사용자

초보 투자자가 입력한 뉴스 문장, 공시 문구, 루머, 우려, 전망을 바로 매수·매도 판단이나 호재/악재 라벨로 연결하지 않고 다음 네 가지로 나눕니다.

1. 공식 앵커 이벤트
2. 비확정 선행 신호
3. 분석 보류/분류 불가
4. 민감정보 포함으로 분석 불가

이후 뉴스/검색으로 선행 신호를 포착하고, OpenDART/KRX/회사 공식 발표로 기준일을 확정한 뒤, 3·5·10영업일 주가증감을 보여줘 사용자가 납득 가능한 투자 판단 과정을 만들도록 돕습니다.

## 선택 기업

카카오페이증권

## 문제 정의

초보 투자자는 매수·매도 결정을 앞두고 뉴스나 문장에서 드러나는 사건을 실제 판단 근거로 사용해도 되는지 구분하기 어렵습니다.

예를 들어 `현대차 파업`이라는 문장은 실제로는 여러 상태일 수 있습니다.

- 파업 가능성
- 임단협 결렬
- 노조 찬반투표
- 실제 생산중단
- 생산재개/타결

이 상태를 구분하지 않으면 사용자는 주가 변화를 특정 뉴스 하나의 결과로 오해할 수 있습니다.

본 플러그인은 사용자의 비정형 입력을 분석 가능한 앵커 이벤트로 매핑할 수 있는지 판단하고, 가능한 경우 최근 1년 유사 앵커 이벤트 이후 3·5·10영업일 주가증감을 제시합니다. 목적은 매수·매도 결론을 대신 내리는 것이 아니라, 사용자가 다음 행동 전에 스스로 납득할 수 있는 판단 근거를 구성하도록 돕는 것입니다.

## 핵심 설계

| 소스 | 역할 | 처리 |
|---|---|---|
| 뉴스/검색 | 선행 신호 포착 | 비확정 선행 신호 |
| OpenDART/KRX/회사 공식 발표 | 기준일 확정 | 확정 앵커 이벤트 |
| 회사/노조 공식 발표 | 합의/철회/타결 기준일 보완 | 회피/합의 시나리오 |
| 시장 데이터 | 주가증감/맥락 확인 | 보조 맥락 |

### 핵심 안전장치

- 뉴스/검색은 선행 신호를 찾는 데 사용하지만, 뉴스만으로 확정 앵커 이벤트를 만들지 않습니다.
- 파업 가능성, 임단협 결렬, 노조 찬반투표, 총파업 예고, 생산 차질 우려는 `생산중단`이 아니라 `비확정 선행 신호`로 처리합니다.
- 비확정 선행 신호는 단순히 분석 보류로 끝내지 않고, 가능한 경우 `파업 발생/생산중단 전환`과 `파업 회피/합의/철회/타결` 두 갈래로 나눠 판단 과정 참고를 제공합니다.
- 두 갈래 모두 예측이 아니라 과거 전개 양상을 판단 전에 확인하기 위한 분류입니다.
- 공식 기준일이 확인되지 않으면 3·5·10영업일 주가증감 수치를 지어내지 않습니다.

### 기준일과 보조 이벤트 규칙

- 이벤트 기준일은 발표 당일을 원칙으로 합니다.
- 장마감 후 또는 휴일에 발표된 이벤트는 다음 영업일을 기준으로 계산합니다.
- 주가증감은 기준일 종가 대비 3·5·10영업일 후 종가 변화로 표시합니다.
- 주가증감을 보여줄 때는 다음 구간의 보조 이벤트를 함께 확인합니다.
  - 기준일 이전 1주일
  - 기준일~3영업일
  - 3~5영업일
  - 5~10영업일
- 보조 이벤트는 인과관계 단정이 아니라 “이 구간의 주가 변화가 독립된 결과가 아닐 수 있다”는 경고로 표시합니다.

### 업종 확장 기준

같은 회사의 최근 1년 유사 사례가 부족해 업종 단위로 확장해야 할 때는 다음 순서를 따릅니다.

1. KRX 업종 분류
2. 카카오페이증권 내부 종목 분류
3. 둘 다 확인할 수 없으면 업종 확장 보류

## 경쟁사/유사 기능 분석

기존 증권 앱과 금융 정보 서비스는 대체로 뉴스, 리포트, 공시, 차트, 가격 변동 사유를 빠르게 보여주는 데 강점이 있습니다.

| 구분 | 일반적인 제공 방식 | 한계 | 본 플러그인의 접근 |
|---|---|---|---|
| 증권 앱 뉴스/공시 탭 | 종목 관련 뉴스와 공시를 시간순으로 제공 | 초보자는 매수·매도 전에 어떤 문장을 판단 근거로 써도 되는지 구분하기 어려움 | 입력 문장을 먼저 공식 앵커 이벤트/비확정 선행 신호/분석 보류로 분류 |
| 주가 급등락 사유 설명 | “이 이슈 때문에 움직였다”는 식의 요약 제공 | 인과관계처럼 보일 수 있고, 중간 이벤트가 빠질 수 있음 | 과거 공식 앵커 이후의 주가증감만 참고값으로 제시하고 보조 이벤트 경고 포함 |
| 뉴스 요약/감성 분석 도구 | 긍정/부정, 호재/악재 성격을 빠르게 분류 | 루머·전망·우려를 확정 사건처럼 오해할 수 있음 | 뉴스는 선행 신호로만 쓰고 기준일은 공식 출처로 확인 |
| 리서치 리포트/전문가 콘텐츠 | 깊이 있는 해설 제공 | 초보자가 매수·매도 전 즉시 구조화해 판단하기에는 진입장벽이 있음 | 사용자의 짧은 문장을 판단 가능한 이벤트 단위로 변환 |

이 플러그인은 “사라/팔아라”를 답하는 기능이 아니라, 초보 투자자가 매수·매도 전에 “이 입력을 판단 근거로 삼아도 되는가”를 검증하고 납득 가능한 판단 과정을 만드는 데 초점을 둡니다.

## 차별점

- 호재/악재를 바로 말하지 않고, 공식 확인 가능성부터 판단합니다.
- 뉴스·루머·전망을 버리지 않되, 확정 사건과 섞지 않고 비확정 선행 신호로 분리합니다.
- 파업처럼 단계가 나뉘는 사건은 `우려/찬반투표`, `생산중단`, `생산재개/타결`을 각각 다른 상태로 처리합니다.
- 비확정 신호는 단순 보류가 아니라, 가능한 경우 전환/회피 시나리오로 나눠 판단 과정 참고자료로 보여줍니다.
- 주가 변화는 수익률 추천이 아니라 기준일 종가 대비 3·5·10영업일 주가증감으로만 표시합니다.
- 구간별 보조 이벤트를 함께 보여줘 사용자가 단일 원인으로 오해하지 않도록 합니다.
- 카카오페이증권의 “초보 투자자의 매수·매도 판단을 돕는 AI” 방향에 맞춰, 결론 추천이 아니라 판단 과정 보조형으로 포지셔닝합니다.

## 부적절한 요청 처리 원칙

다음 요청은 결과를 제한하거나 거절합니다.

- 특정 종목의 매수·매도·보유 여부를 직접 묻는 요청
- 목표가, 손절가, 수익률 보장, 단기 급등 종목 추천 요청
- 공식 출처가 없는데도 확정 사건처럼 계산해 달라는 요청
- 루머, 미확인 찌라시, 커뮤니티 글만으로 주가 영향을 단정해 달라는 요청
- 내부자 정보, 비공개 정보, 위법 가능성이 있는 정보 활용 요청
- 계좌번호, 비밀번호, 인증번호, 주민등록번호, 전화번호, 이메일, 보유수량, 평균단가, 평가금액, 손익률 등 개인·계좌·인증 정보가 포함된 요청

처리 방식:

- 투자 판단 요청은 매수·매도 결론이 아니라 사건 검증과 과거 주가증감 참고로 범위를 낮춰 안내합니다.
- 공식 기준일이 없으면 수치를 만들지 않고 `공식 출처 확인 필요`로 표시합니다.
- 회사명, 이벤트 유형, 기준일 후보가 불명확하면 추가 입력을 요청하거나 분석 보류로 처리합니다.
- 이미지/사진/캡처에 민감정보가 보이면 분석하지 않고 삭제 또는 민감정보 제거 후 재업로드를 안내합니다.
- 텍스트에 민감정보가 포함되어 있으면 해당 부분을 `*`로 마스킹하고 `민감정보 포함으로 분석 불가` 상태로 처리합니다.
- 민감정보가 포함된 입력은 앵커 이벤트 분석 대상이 아니며, 회사명과 사건 문장만 다시 입력하도록 안내합니다.
- 결과 하단에는 항상 예측·투자 권유가 아니라는 고지를 표시합니다.

## 예시: 현대차 파업

OpenDART 연결 전에는 `현대차 파업`을 비확정 선행 신호로만 다뤘습니다.

OpenDART 연결 후에는 다음 공식 공시를 확인했습니다.

| 구분 | 기준일 | 공시 | 핵심 내용 |
|---|---:|---|---|
| 생산중단 | 2025-09-03 | 생산중단 | 단체교섭 등 관련 부분파업 |
| 생산재개/타결 | 2025-09-16 | 생산재개(자율공시) | 단체교섭 관련 부분파업 종료, 최종 타결일 |

주가증감 예시:

| 기준 사건 | 기준 종가 | +3영업일 | +5영업일 | +10영업일 |
|---|---:|---:|---:|---:|
| 2025-09-03 생산중단 | 221,500원 | -3,000원 / -1.35% | -1,000원 / -0.45% | -5,500원 / -2.48% |
| 2025-09-16 생산재개/타결 | 215,000원 | +3,000원 / +1.40% | +2,500원 / +1.16% | +500원 / +0.23% |

이 수치는 예측이나 투자 권유가 아니라, 과거 공식 앵커 이벤트 이후의 주가증감 참고값입니다.

## 실행 준비

OpenDART API 키는 제출물에 포함하지 않습니다.

로컬에서 실행할 때는 `src/.env.example`을 참고해 `.env`를 만들고 다음 값을 설정합니다.

```env
OPENDART_API_KEY=your_40_character_opendart_api_key
```

## 포함 스크립트

- `src/scripts/opendart_search.py`
  - `.env`에서 `OPENDART_API_KEY`를 읽습니다.
  - OpenDART `corpCode.xml`로 회사 고유번호를 찾습니다.
  - OpenDART `list.json`으로 최근 공시를 조회합니다.
  - 생산중단/영업정지/조업중단/주요사항보고/거래소공시 후보를 필터링합니다.

- `src/scripts/calc_event_impacts.py`
  - 공개 가격 데이터를 사용해 기준일 이후 3·5·10영업일 종가 증감을 계산하는 테스트 스크립트입니다.

## 해커톤 질문 5문항

### 1. 무엇을, 누가, 어떤 상황에서 쓰나요?

초보 주식거래자와 주식 공부 중인 사용자가 매수·매도 결정을 앞두고 뉴스 제목, 기사 일부, 공시 문구, 커뮤니티 문장을 보고 “이걸 판단 근거로 써도 되는지” 판단하기 어려울 때 사용합니다.

예: `현대차 파업`, `삼성전자 최대 실적`, `금리 인하 기대`, `수주설`

### 2. 왜 이 문제를 선택했나요?

주식 초보자는 매수·매도 전에 접한 뉴스를 단순히 호재/악재로 판단하기 쉽습니다. 하지만 실제 주가는 뉴스의 표면적 긍정·부정뿐 아니라 선반영, 공식 확인 여부, 중간 이벤트, 시장 맥락에 영향을 받습니다.

카카오페이증권은 초보 투자자에게 매수·매도 결론을 직접 지시하기보다, 사용자가 안심하고 다음 행동을 검토할 수 있도록 판단 과정을 구조화하는 AI 경험을 제공할 수 있습니다.

### 3. 플러그인은 어떻게 작동하나요?

1. 사용자가 회사명과 비정형 이벤트 문장을 입력합니다.
2. 플러그인이 입력을 공식 앵커 이벤트, 비확정 선행 신호, 분석 보류로 분류합니다.
3. 뉴스/검색은 선행 신호 포착에 사용합니다.
4. OpenDART/KRX/회사 공식 발표로 기준일을 확정합니다.
5. 기준일 이후 3·5·10영업일 주가증감을 계산합니다.
6. 기준일 이전 1주일과 이후 3·5·10영업일 구간의 보조 이벤트와 시장 맥락을 함께 안내합니다.
7. 비확정 선행 신호는 확정 앵커로 단정하지 않고, 가능한 경우 전환/회피 시나리오로 분리해 설명합니다.

### 4. AI를 어떻게 활용했나요?

AI를 사용해 문제 정의를 좁히고, 리스크를 식별하고, 앵커 이벤트 체계와 사용자 응답 형식을 설계했습니다.

특히 “호재/악재 판단”에서 출발한 아이디어를 “매수·매도 전 판단 근거로 사용할 수 있는 사건인지 검증하는 앵커 이벤트 매핑 플러그인”으로 재정의했습니다.

### 5. 어떻게 검증했나요?

다음 방식으로 검증했습니다.

- 10개 국내 기업 사건에 대해 앵커 매핑 테스트
- 현대차 파업 사례에 대해 OpenDART 실제 API 연결
- 현대차 생산중단/생산재개 공시 원문 확인
- 기준일 이후 3·5·10영업일 주가증감 계산
- 플러그인 validation 통과

검증 결과는 `OPENDART_HYUNDAI_STRIKE_REALDATA_RESULT.md`와 `PLUGIN_TEST_RESULTS.md`에 정리했습니다.

## 주의

- 이 플러그인은 투자 권유나 매수·매도 추천을 하지 않습니다.
- 과거 주가증감은 미래 예측이 아닙니다.
- 뉴스/검색으로 포착한 신호는 확정 이벤트가 아닙니다.
- 공식 기준일이 없는 경우 수치를 지어내지 않습니다.
- `.env`와 API 키는 제출물에 포함하지 않습니다.

## 향후 운영·업데이트 방향

MVP 이후에는 다음 방향으로 확장할 수 있습니다. 단, 현재 제출물에서는 방향성 제시 수준이며 자동 투자 판단 기능으로 확장하지 않습니다.

- 앵커 이벤트 사전 확장: 공급계약, 자사주, 증자, 배당, 소송 등 이벤트별 포함/제외 조건 고도화
- 공식 출처 확대: OpenDART 외 KRX, 회사 IR, 한국은행, 통계청, 금융위원회 등 공식 기준일 소스 보강
- RSS 재검토: 저작권, 원문 저장, 중복 기사, 오염 검색어 문제를 해결할 수 있다면 뉴스 RSS를 비확정 선행 신호 포착용으로 제한적으로 활용
- 품질 관리: 오매핑 사례를 모아 앵커 사전과 보류 조건을 지속 업데이트
- 사용자 교육 강화: “왜 이 입력은 확정 사건이 아닌지”를 더 쉽게 설명하는 예시 카드 추가
- 운영 안전장치: 투자 추천으로 오해될 표현을 점검하고, 응답마다 예측 아님·투자 권유 아님 고지 유지

## OpenAI LLM 보조판단 설정

API 키는 채팅이나 커밋에 직접 붙이지 말고, git에서 제외된 `.env` 파일에만 넣는다.

```env
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-5-mini
```

실행:

```bash
python3 scripts/context_signal_pipeline.py \
  --company SK하이닉스 \
  --ticker 000660 \
  --sentence "엔비디아 HBM 수요 확대는 SK하이닉스에 좋은 이슈야?" \
  --date 2025-04-04 \
  --rss \
  --llm
```

주의: 한 번 채팅이나 로그에 노출된 API 키는 폐기하고 새 키로 교체하는 것이 안전하다.

## AI 상황 파급 지도 + PDF 리포트

종목 하나의 호재/악재 뉴스 분류를 넘어, 하나의 상황이 어떤 산업과 종목군으로 번질 수 있는지 AI가 파급 지도를 생성한다. 결과는 JSON과 PDF로 저장된다.

```bash
python3 scripts/situation_impact_pipeline.py \
  --situation "엔비디아 HBM 수요 확대가 한국 주식시장에 어떻게 번질까?" \
  --date 2025-04-04 \
  --max-candidates 6
```

출력물:

- `output/situation/*.json`: 구조화된 상황 파급 지도
- `output/pdf/*.pdf`: 가독성용 PDF 리포트

저장된 JSON에서 PDF만 다시 만들 때는 API를 재호출하지 않는다.

```bash
python3 scripts/situation_impact_pipeline.py \
  --from-json output/situation/example.json \
  --pdf-output output/pdf/example.pdf
```

상황 지도는 투자 추천이나 가격 예측이 아니라, `상황 -> 영향 단계 -> 후보 산업/종목 -> 확인 데이터`를 정리하는 가설 지도다.

## 5개 회사 상황 신호 배치 리포트

여러 회사를 한 번에 비교할 때는 배치 리포트를 생성한다. 기본 대상은 SK하이닉스, 삼성전자, 카카오, 한화오션, LG에너지솔루션이다.

```bash
python3 scripts/company_context_batch_report.py
```

출력물:

- `output/company_batch/*.json`: 회사별 카드 원본과 요약
- `output/pdf/*_five_company_context.pdf`: 비교용 PDF 리포트

저장된 JSON에서 PDF만 다시 만들 때는 API를 재호출하지 않는다.

```bash
python3 scripts/company_context_batch_report.py \
  --from-json output/company_batch/example.json \
  --pdf-output output/pdf/example.pdf
```

LLM 호출이 지연되거나 실패하면 보고서는 중단하지 않고 규칙 기반 백업 신호를 표시한다. 이 경우 해당 회사의 판단 신뢰도는 낮게 보고, 공시·실적·정책 원문 확인이 필요하다.

## 라벨셋 평가 테스트벤치

차터가 말로만 맞는지 확인하기 위해 라벨셋 평가기를 둔다. RSS/LLM/API 호출 없이 현재 룰 기반 파이프라인을 빠르게 평가한다.

기본 starter taxonomy 200건 실행:

```bash
python3 scripts/labelset_evaluation.py --limit 200
```

외부 라벨셋 템플릿 생성:

```bash
python3 scripts/labelset_evaluation.py \
  --write-template output/labelset/labelset_template.json
```

외부 라벨셋 평가:

```bash
python3 scripts/labelset_evaluation.py \
  --labelset-json path/to/labelset.json
```

외부 라벨셋은 회사, 종목코드, 입력 문장, 기대 라벨을 담은 JSON이다. 기대 라벨은 출발점, 확인도, 방향성, 영향 거리, 회사 관련성, 필수 확인 데이터, 안전성으로 구성한다.

첫 기준선 결과에서는 방향성과 관련 낮음 방어가 가장 약했다. 이후 파급 경로 기반 관련성 게이트를 `0~5차 영향 단계` 평가로 확장했다. 최신 starter taxonomy 200건 기준, 방향성 정확도는 `90.0%`, 영향 단계 정확도는 `99.0%`, ±1단계 허용 정확도는 `100.0%`, 5차 관찰 전용 방어는 `100.0%`다. 다음 개선은 출발점 taxonomy/라벨 매핑 정리다.
